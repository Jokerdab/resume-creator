# Скилл «Резюме под вакансию»

ИИ-агент (Cursor, Claude Code и похожие) собирает резюме под конкретную вакансию по твоему опыту: подбирает заголовок, summary, порядок и формулировки результатов под требования, рендерит PDF на 2 страницы и честно говорит, чего в твоём опыте для этой вакансии не хватает.

Главное правило: в резюме попадает только то, что записано в твоём банке фактов. Нет цифры — нет утверждения.

## Что внутри

```
Скилл для резюме/
├── SKILL.md                        инструкция для агента (все правила)
├── README.md                       этот файл
├── facts/
│   ├── fact_bank.md                твой банк фактов — сначала пустой
│   └── gold_example_fact_bank.md   эталон: как выглядит хорошо заполненный банк
├── templates/
│   ├── standard.html               режим «стандарт» (по умолчанию)
│   ├── bento.html                  режим «бенто»: плитки с цифрами, карточки опыта
│   └── boring.html                 режим «скучный»: как документ Google Docs
├── output/                         сюда агент кладёт результат, по папке на дату
│   ├── 2026-11-04/                 пример: резюме под вакансии в стандарте и в бенто
│   └── 2026-11-05/                 пример: базовое резюме во всех трёх режимах
└── scripts/
    ├── render.sh                   HTML → PDF и проверка, что вышло 2 страницы
    ├── ats_check.py                проверка, как резюме прочитает ATS, и покрытие слов вакансии
    └── example_ats_keywords.txt    пример файла ключевых слов вакансии
```

## Что нужно

- Агент, который читает файлы и запускает команды в терминале (Cursor, Claude Code).
- Google Chrome или Chromium — для рендера PDF.
- Python 3 — скрипт считает страницы.

## Как подключить

**Cursor.** Скопируй папку в `.cursor/skills/resume-vacancy-tailor/` своего проекта (или в `~/.cursor/skills/`). Агент подхватит `SKILL.md` сам, когда ты пришлёшь вакансию. Можно и без копирования: открой эту папку в Cursor и напиши «работай по SKILL.md».

**Другие агенты.** Открой папку как рабочую и первым сообщением напиши: «Прочитай SKILL.md и работай по нему».

## Первый запуск: заполнение опыта

Банк фактов сначала пустой (`STATUS: EMPTY`). Пока он не заполнен, агент не собирает резюме, а предлагает два пути:

1. **Прикрепить текущее резюме** (PDF, DOCX, текст или выгрузку из LinkedIn). Агент разложит его по банку фактов, проверит по эталону и задаст вопросы там, где не хватает цифр. Это быстрее.
2. **Ответить на вопросы.** Агент проводит интервью по каждому месту работы: что за продукт, какая была цель, какая команда, что ты сделал и какие метрики сдвинулись.

После этого агент собирает базовое резюме в режиме «стандарт» и кладёт его в `output/<сегодняшняя дата>/`.

## Проверка опыта

Напиши «проверь мой опыт», и агент оценит каждое место работы по 8 критериям: понятно ли, что за продукт, есть ли цель, есть ли команда, есть ли результаты «до → после», понятен ли контекст у цифр, связаны ли цель и результат, нет ли пустых фраз вроде «responsible for», нет ли утверждений без фактов.

На выходе таблица со статусами зелёный / жёлтый / красный, вопросы к тебе и варианты «было → станет». Там, где цифры неизвестны, стоят пропуски `[?]`: агент не придумывает цифры за тебя.

## Как пользоваться дальше

Пришли агенту вакансию:

```
- Компания
- Роль <название>
- Описание вакансии: задачи / требования / будет плюсом
- Режим: стандарт / бенто / скучный   (необязательно, по умолчанию стандарт)
```

Агент:
1. разбирает требования вакансии и сопоставляет их с твоими фактами;
2. собирает резюме в `output/<дата>/<Компания>_<Имя>_<Фамилия>_Resume_<Роль>.html` и `.pdf`;
3. проверяет, что вышло 2 страницы;
4. пишет отчёт: что закрыто, чего не хватает и как об этом сказать на интервью, а в конце — решение `go`, `iterate` или `stop`.

Если вакансия сильно не про тебя, агент так и скажет (`stop`). Это нормально: так ты не тратишь время на отклик, который не сработает.

## Проверка под ATS

Перед отчётом агент читает готовый PDF так, как его читает система отбора резюме (ATS): находятся ли контакты, заголовки разделов, даты, название вакансии и слова из требований. Порог: все пункты разбора в порядке, покрытие слов вакансии не ниже 80%, обязательных — не ниже 90%. Если слова нет, потому что нет такого опыта, агент не дописывает его ради процента, а пишет это в gaps.

Вручную:

```bash
python3 scripts/ats_check.py output/<дата>/<файл>.pdf output/<дата>/<файл>_ATS_keywords.txt
```

## Режимы

| Режим | Когда |
|---|---|
| Стандарт | По умолчанию: банки, корпорации, порталы с автоматическим разбором резюме (ATS) |
| Бенто | Продуктовые и tech-компании, где хочется выделиться визуально |
| Скучный | Строгие ATS-порталы или проверка, какой вариант лучше читается |

## Рендер вручную

```bash
bash scripts/render.sh output/2026-11-04/*.html
```

## Про эталоны

`facts/gold_example_fact_bank.md` — вымышленный персонаж с условными цифрами: по нему видно, какого уровня конкретики добиваться. Файлы в `output/` — реальные примеры готовых резюме автора скилла. Чужие факты в своё резюме не переносить; свои результаты агент положит в `output/` рядом.
